# 全面升级：非阻塞 AI、悬浮工具坞、组合模式、UI 重设计、科研图质量

**日期**：2026-08-06
**状态**：已批准（brainstorming 逐项确认）
**范围**：9 个子项目，一次实施计划完成

## 背景与目标

用户对现有科研制图工具的批量升级请求，经 brainstorming 逐项确认：

| 问题 | 决定 |
|---|---|
| 对话区重设计 | **B 玻璃层次**（Linear 质感：面板分层、消息胶囊带柔影、模式按钮带图标） |
| AI 模式选择 | **B 多选组合**（胶囊多选，AI 在所选图种内自由组合） |
| 编辑栏分组 | **C 悬浮玻璃坞**（顶栏仅画布/导出/设置；左侧竖排坞：工具+编辑+图表） |
| 属性面板 | **A 分段卡片**（类型徽章 + 外观/文字/排列分节 + 预设科研色板） |
| 操作气泡 | **C 可展开时间线**（折叠单行，展开全部步骤，逐动作动画） |
| 图表编辑 | **数据表对话框**（工具生成 + 点图表「编辑数据」整图重排） |
| AI 非阻塞 | 生成中可平移/缩放/画新元素；**AI 正在编辑的元素锁定并高亮**；AI 最小改动用户操作 |
| 破坏性确认 | **画布级 + 删元素**弹确认框（人话描述，可取消） |

## 子项目 1：AI 非阻塞操作 + AI 元素锁定/高亮

### 需求
- AI 生成过程中画布不再整体锁定：可平移、缩放、画新元素、编辑用户自己的元素。
- AI 本轮生成创建/修改过的元素**锁定**：不可选中、不可拖动、不可编辑，避免与流式应用冲突。
- 锁定的元素**高亮**显示，让用户知道哪些是 AI 正在动的。
- AI 秉持**最小改动用户操作**的原则（prompt + 工具约束）：只动用户要求的内容；未要求的一律不动；用户明确要求大改（新建画布/清空/整图重排）除外且走确认对话框。
- 生成中撤销/重做禁用（保持"生成完成后 Ctrl+Z 一步整体撤销"）。

### 设计
- store 新增 `aiLockedIds: string[]`（本轮生成 AI 触及的元素 id）。draft 流式 op 应用时把涉及 id 加入。
- 交互层：`usePointerInteraction` / `SelectionOverlay` / `Canvas` 命中检测跳过锁定元素（点击、框选、拖动、缩放、触点拉箭头均不响应）；`setSelection` 过滤锁定 id；锁定元素被框选时自动剔除。
- 视觉：锁定元素渲染加 `ai-locked` 类 → 细虚线蓝描边 + 呼吸动画（透明度轻微脉动，克制）。
- 生成结束（`isGenerating` 置 false）时清空 `aiLockedIds`。
- 本地删除与 AI 冲突：前端 op 应用时元素 id 不存在则跳过（服务端 draft 不一致是已知可接受的局部差异）。
- 撤销/重做按钮在 `isGenerating` 时禁用（CSS + 快捷键守卫）。

### 测试要点
- 生成中锁定元素不可选中/拖动（pointerdown 无响应）。
- 框选自动剔除锁定元素。
- 生成结束解锁。
- 撤销/重做生成中禁用。

## 子项目 2：悬浮玻璃坞（工具栏分组重设计）

### 需求
- 顶栏只保留：画布切换（下拉 + 新建/重命名/删除）+ 导出（SVG/PNG）+ 设置。
- 左侧竖排悬浮玻璃坞：**工具**（图案+逻辑合并的主按钮，气泡内分两区）、**编辑**（撤销/重做）、**图表**（新增，打开数据表对话框）。
- 修复"图案/逻辑按钮展开后内容重叠"的 bug。

### 设计
- 顶栏与左侧坞均用现有 `.glass-panel` 语言（半透明 + blur + 内高光 + 外投影）。
- 工具主按钮：点击展开气泡，气泡内分两区——「图案」小标题下 9 个形状按钮、「逻辑」小标题下逻辑节点按钮；点主按钮开关、点外 pointerdown 关闭（沿用现有非阻塞气泡机制）。
- 坞容器 `relative z-40`（沿用 Task 41 的 stacking context 修复），气泡 `absolute left-full top-0`（向右展开，不覆盖画布顶部）。
- 重叠 bug 修复：气泡 z-index 高于画布区，且坞内按钮 flex 排列间距正确（实现时 dev 验证）。
- 图表按钮：打开图表数据表对话框（见子项目 7）。

### 测试要点
- 工具气泡展开后图案/逻辑两区不重叠、不被画布遮挡。
- 切换子工具后主按钮图标更新。
- 顶栏各功能（画布切换/导出/设置）可用。

## 子项目 3：破坏性 AI 操作确认对话框

### 需求
- AI 要执行**新建画布 / 清空画布 / 删除已有元素**时，先弹确认框：人话描述"即将做什么"，用户可取消。
- 确认后继续执行；取消则该操作跳过（AI 其余工作继续）。
- 删除的"已有元素"指用户自己创建的元素；AI 本轮刚创建的（在 aiLockedIds 中）删除不需要确认。

### 设计（两阶段流）
1. 服务端 `runAgent` 的工具执行器（draft.ts）遇到三类破坏性操作时：不直接执行，记录到 `pendingConfirms: { id, description }[]` 并给模型返回"操作已挂起，等待用户确认"的提示，模型继续其他工作。生成流结束前若仍有挂起项，流中追加一条 `{"type":"confirm-request","pending":[...]}` 消息，生成结束（会话存到内存 `pendingSessions: Map<sessionId, { draft, pending }>`）。
2. 前端收到 confirm-request 后弹玻璃确认框（人话描述 + 取消/确认按钮）；用户选择后 POST `/api/chat/confirm`（sessionId + 每项 approved 布尔）。服务端对 approved 项执行对应 draft 操作并流式回发 op 事件，前端照常应用；随后追加一条系统消息"已确认/已取消：<描述>"。
- 新组件 `ConfirmDialog`：玻璃风格（沿用 `.glass-panel` 语言），居中弹层，人话描述 + 取消/确认按钮（确认红/蓝区分危险度），多条挂起项逐条列出可分别确认。
- 描述由执行器生成人话文案，例如：
  - 新建画布：「新建画布并切换到『Transformer 架构图』」
  - 清空画布：「清空当前画布（将删除 12 个元素）」
  - 删除元素：「删除 2 个元素：『旧模块』逻辑节点、『说明文字』文字」
- 前端本地（非 AI）的删除画布等操作继续用现有 window.confirm（不改）。

### 测试要点
- 确认流：confirm-request 消息体 → 对话框出现 → 确认后 op 应用 → 系统消息。
- 取消流：取消后该操作不应用，其余工作完成。
- 无破坏性操作时不发 confirm-request。
- 本轮 AI 创建元素的删除不触发确认。

## 子项目 4：AI 模式多选组合

### 需求
- 模式选择从单选改**多选**：四个胶囊（自动 / 科研绘图 / 思维导图 / 图表制作）可同时点亮多个具体模式；「自动」互斥（点亮自动 = 清空具体选择，点具体 = 清空自动）。
- AI 在所选图种内**自由组合**：科研图中可内嵌图表小节、思维导图分支中可加入示意图、图表制作中可配流程图说明——以此类推，不只限于列举的组合。
- 选择随画布持久化（沿用 `chartMode-<projectId>`，值改为 JSON 数组；读取时兼容旧格式字符串 → 转数组）。

### 设计
- ChatPanel：`selectedModes: Set<AIMode>` + `auto: boolean`（默认自动）。胶囊 UI 带图标（见子项目 5），激活态蓝底。
- fetch body：`modes: AIMode[] | null`（null = 自动）。
- prompt.ts：`buildSystemPrompt(modes?: AIMode[])`——具体模式时拼对应节的规范 + 新增**组合规范节**：「你可以在主图种中内嵌其他图种的小节（例如科研流程中嵌入数据图表、思维导图分支中嵌入详细示意图、图表旁配流程图说明）。内嵌小节风格与整体一致（同色板/同线宽/同字号体系）。」
- agent.ts：`modes` 透传。

### 测试要点
- 多选交互：点具体模式清自动、点自动清全部具体。
- localStorage 存取（合法值校验）。
- buildSystemPrompt 组合节：具体模式含对应节 + 组合节；自动不含组合节。
- agent 透传 modes。

## 子项目 5：对话区玻璃层次重设计

### 需求
- ChatPanel 重做（方向 B）：面板分三层——模式选择条（标题区）/ 消息流 / 输入区，各自半透明层次。
- 消息改胶囊：用户右对齐蓝底白字带柔影，AI 左对齐 surface 色；AI 流式进行中显示呼吸光标。
- 模式按钮带图标（自动 = 星标/魔法棒、科研绘图 = 烧瓶、思维导图 = 节点、图表 = 柱状）。

### 设计

- 消息流：玻璃面板内滚动区；消息胶囊圆角（用户 12/12/4/12，AI 12/12/12/4）+ 柔影。
- 输入区：毛玻璃输入框 + 生成按钮（沿用现有行为：NDJSON 流式、错误显示）。
- 动画沿用：`msg-in` 淡入上浮。

### 测试要点
- 模式图标渲染；多选状态样式。
- 消息胶囊左右区分；流式光标。
- 既有面板测试（panels.test.tsx）适配新结构。

## 子项目 6：属性面板分段卡片重设计

### 需求
- 属性面板改为分段卡片（方向 A）：顶部类型徽章；小标题分节——**外观 / 文字 / 排列（多选时）/ 数据（图表元素）/ 操作**。
- 外观：预设科研色板圆点（#eef4ff 蓝 / #f0fff0 绿 / #fff8e6 橙 / #f3efff 紫 / #ffeef0 红 / 白）+ 自定义取色器 + 滑块带数值（线宽/圆角/透明度/旋转）。
- 文字：内容输入 + B/I + 字号 + 对齐（仅 text/logic）。
- 排列（多选）：6 对齐 + 2 分布图标按钮（沿用现有实现）。
- 操作：删除（红）+ 取消选择。

### 设计
- 各节卡片化（圆角胶囊背景，节间留白，小标题 10px 灰色大写感）。
- 滑块行：标签 + 滑块 + 数值，行内布局；数值输入与滑块双向同步。
- 类型徽章：中文类型名（逻辑节点/文字/矩形/…）+ 类型专属标识。
- 图表元素选中且共享同一 chartId 时显示**数据**节：「编辑图表数据」按钮 → 打开数据表对话框（子项目 7）。

### 测试要点
- 各类型显示对应节；多选显示排列节。
- 滑块与数值同步；预设色板点击设置 fill。
- 图表元素显示数据节。

## 子项目 7：图表数据表对话框（用户添加/编辑图表）

### 需求
- 用户可**手动添加图表**：左侧坞「图表」按钮 → 对话框选类型（柱状/折线/饼/散点）+ 填数据表（行：标签+数值，可增删行）→ 生成图表元素（复用 chartLayout）。
- 用户可**编辑已有图表**：选中图表任一元素 → 属性面板「编辑图表数据」→ 同一对话框预填 → 保存后整图按数据重排。
- 元素本身仍可自由改样式/移动（保留图表元素可编辑性）。

### 设计
- types.ts：`CanvasElement` 增可选字段 `chartId?: string`；`CanvasDoc` 增 `charts: Record<string, ChartSpec>`（chartId → 类型+数据，重排依据）。
- draft.ts applyChart 生成元素时写入 chartId 并登记 charts。
- 新组件 `ChartDialog`：类型胶囊 + 数据表格（行增删、标签/数值输入，校验：非负、标签非空、行数 3~12、饼图总和 >0）+ 生成/保存按钮。手动生成 = 前端调 chartLayout 生成元素（一步撤销，入历史）。
- 重排逻辑：取 charts[id] → chartLayout 重算 → 该 chartId 的全部旧元素删除 + 新元素创建（commitHistory 一次，一步撤销）。
- 数据表对话框与 AI 生成共用校验规则（非负/空标签/零总和），复用 draft.ts 的校验函数或抽到独立模块。

### 测试要点
- 手动生成图表：类型/数据 → 元素 + charts 登记。
- 编辑重排：改数据 → 旧元素删除新元素生成，一步撤销。
- 校验错误提示（非负/行数/空标签/零总和）。
- 图表元素可自由移动/改样式。

## 子项目 8：操作气泡可展开时间线

### 需求
- 左下角气泡重做（方向 C）：折叠时显示最新一条动作（带呼吸蓝点）；点击展开完整垂直时间线（每步 ✓，最新一步蓝点高亮）。
- 每来一个新动作，气泡内新条目滑入弹出（旧条目上移，动画 240ms 淡入 + translateY）。
- 活动文案更详细、说人话：说清**在哪创建了什么、写了什么文字**，例如「在 (760, 200) 创建逻辑节点『多头注意力』，标题加粗 14px」「在 (300, 500) 添加文字『准确率 92.3%』」。
- 时间线上限 ~30 条，超出折叠更早条目。

### 设计
- GenerationToast 重写：折叠态（最新一条 + ▾ 展开箭头）/ 展开态（时间线）。点击切换；生成结束后保留时间线（新增动作时气泡自动弹出）。
- 动画：`toast-in` 类（translateY(8px)→0 + 淡入 240ms）。
- 活动文案丰富化：draft.ts 各工具的 activity 字符串升级为"坐标 + 类型 + 标题/文字内容 + 关键属性"格式；applyGraph/applyMindMap/applyChart 的活动摘要同样人话化（「完成流程图：4 个节点、3 条连线，自动对齐」）。
- 点击聚焦聊天输入框的行为移除（气泡点击 = 展开/收起）。

### 测试要点
- 折叠/展开切换；新动作滑入动画类存在。
- 活动文案含坐标与内容（工具单测断言 activity 格式）。
- 30 条上限折叠。

## 子项目 9：科研绘图质量提升（prompt 强化）

### 依据（GitHub 调研）
- baoyu-diagram（2.4 万 star）：**硬性数字规则**是核心——盒高 50-70px、垂直间距 ≥40px、viewBox padding 30px、标题 16/正文 11-12px；自检清单 3 条（无重叠/图例不越界/viewBox 够大）。
- academic-figure-skill：克制配色（2-4 语义色 + 1 强调色）、一幅图一个核心信息、禁默认色板/空盒子。
- 两阶段生成 + 交付前检查表。

### 设计（全部落在 prompt.ts）
- **科研审美规范强化为硬数字**：
  - 逻辑节点尺寸统一：同流程宽 150~180、高 48~60，标题 14px 加粗、正文 11px；间距 20~60px 统一。
  - 文字：标题 ≤8 字、正文每行 ≤14 字；文字宽度按估算公式（中文 1×字号、大写 0.68、小写 0.55、数字 0.6、空格 0.32，加粗 ×1.06）。
  - 配色：同图 ≤3 色（语义色）+ 边框统一 #2f2f2f 1px；折线/散点用深色描边色板。
  - 箭头线宽 1.5、箭头大小适中。
- **自检清单注入**（生成完自查并修正，最多 1 轮）：无重叠、模块内必须有内容（禁空盒子）、文字不溢出模块、整体不超画布、图例不越界；发现用 updateElement 修正。
- **两阶段引导**：先在心里/活动日志规划布局（组件清单 + 流向 + 大致坐标）再开始创建元素。
- 图表/导图规范沿用现有节，与硬数字保持一致。

### 测试要点
- buildSystemPrompt 输出含硬数字规则与自检清单（字符串断言）。
- 现有 agent 测试不回归。

## 非目标
- 不做图层（z 序管理）功能。
- 不做图表分组容器（元素保持扁平、自由编辑）。
- 不做多用户/云同步。
- 不改造启动器。

## 验收清单
1. AI 生成中画布可平移/缩放/画新元素；AI 元素锁定 + 高亮；生成完解锁。
2. AI 新建画布/清空/删用户元素前弹确认框，取消不执行。
3. 模式多选 + 自动互斥；AI 按所选图种组合（实测：科研图内嵌图表、导图分支嵌入示意图）。
4. 对话区玻璃三层结构、消息胶囊、模式图标。
5. 左侧悬浮坞 + 工具气泡两区不重叠；顶栏精简。
6. 属性面板分段卡片 + 预设色板 + 滑块；图表元素有「编辑图表数据」。
7. 图表数据表对话框：手动生成 + 编辑重排均可。
8. 操作气泡时间线：折叠/展开、逐动作动画、人话详情（坐标+内容）。
9. 科研图质量实测：AI 生成一张流程图，节点统一、间距统一、配色克制、无重叠。
10. `npm test` 全绿；`next dev -p 3001` 编译通过。
