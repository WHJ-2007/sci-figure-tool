# 启动器优化设计（深色亚克力 + 去卡顿）

日期：2026-08-06

## 背景

科研制图工具的 PowerShell WinForms 启动器（`tools/launcher/launcher.ps1`）存在两个问题：

1. **慢**：1.5s 定时器每次 `& check-launcher.ps1` 同步拉起全新 PowerShell 子进程轮询状态。实测单次子进程调用约 **3.1 秒**（进程内直接调用仅 0.26 秒），UI 线程每 tick 被阻塞 3 秒以上，窗口长期处于冻结状态。
2. **不美观**：默认 WinForms 灰底 + FixedSingle 边框 + 原生按钮，与网页应用（亚克力面板/玻璃边缘/科研深色审美）气质不一致。

## 目标

- 性能：状态轮询改为进程内调用，定时器毫秒级返回，UI 永不冻结。
- 美观：深色亚克力（Win11 原生 DWM 亚克力背景 + 深色标题栏 + 圆角按钮 + 状态胶囊），与网页应用视觉一致。
- 功能：启动后自动打开浏览器；新增"打开项目目录"按钮。
- 不改变 `launcher-core.ps1` 任何逻辑（纯函数保持零改动），`test-core.ps1` 11 项全绿不受影响。

## 方案

### 性能改造（去除子进程轮询）

- 定时器每 tick 只做**进程存活检查**：直接调用 `Load-PidFile` / `Is-ProcessAlive`（core 已点源进 GUI 进程），不再 `& check-launcher.ps1`。
- **端口占用检查**（`Get-NetTCPConnection` 约 100ms）只在点"启动"按钮时执行——原版每 tick 查端口但结果不在界面展示，纯浪费。
- 日志读取保留 `Get-Content -Tail`（高效，且有 try/catch）。
- `check-launcher.ps1` 保留供调试/其他用途，GUI 不再调用。

### 视觉改造（Win11 原生 DWM）

- **标题栏**：`DWMWA_USE_IMMERSIVE_DARK_MODE`(attr 20) → Win11 深色标题栏。
- **窗口背景**：`DWMWA_SYSTEMBACKDROP_TYPE`(attr 38) = ACRYLIC(3)；调用失败降级 Mica(2) → 纯色 `#1A1B21`（P/Invoke 全部 try/catch）。
- **状态胶囊**：Label 用 `●`(U+25CF) 圆点 + 状态色：绿=运行中 / 黄=启动中 / 红=错误 / 灰=已停止；显示 PID 与 URL。
- **日志区**：TextBox 深色底（约 `#0D1117`）+ 浅色文字 + Consolas 等宽字体，`FixedSingle` 边框。
- **按钮**：`FlatStyle.Flat` + `Paint` 自绘圆角（6px）+ hover/按下状态色；主按钮深蓝（#2563EB）、停止红（#DC2626）、其余中性。
- **字体**：Microsoft YaHei UI 10pt，标题 11pt 加粗。
- 保留原生标题栏（可拖动），不做自定义无边框标题栏。

### 功能

- 点"启动"成功（PID 已保存、进程已拉起）后自动 `Start-Process (Get-ServerUrl)`。
- 新增"打开项目目录"按钮：`explorer.exe <Get-ProjectRoot>`。

## 测试

- `test-launcher.ps1` 现有 4 项静态断言保持全绿（存在 / BOM / 语法解析 / core BOM）。
- 新增 1 项防回归断言：launcher.ps1 中不再出现对 `check-launcher.ps1` 的子进程调用（`& "$PSScriptRoot\check-launcher.ps1"`）。
- `test-core.ps1` 11 项不受影响。
- 验证方式：`powershell -NoProfile -ExecutionPolicy Bypass -File tools\launcher\test-launcher.ps1` 与 `test-core.ps1` 全绿；实际双击 `启动器.bat` 走查启动/自动开浏览器/停止/打开项目目录四条路径。
